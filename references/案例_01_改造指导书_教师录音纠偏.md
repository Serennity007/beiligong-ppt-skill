### 一、此次改造要解决什么

这份材料用于作技术安全报告。听众应能沿着一条清楚的主线，理解技术构成、安全问题及防控方案。

当前主要问题是：目录混入了改稿索引，内容开始前缺少统摄关系的总图；每页独立改写大标题，反而削弱了同一主题下的连续讲述；绿色与灰色底块过多，文字不清楚；部分案例没有直接交代问题与方案。此次先纠正这些问题，不以增加页数、增加图数或更换几个标题代替结构改造。

教师要求的依据：

- “我让你给个总图，不是让你加一个小目录。”
- “你得先画一个总图，然后依照这个总图，我展开讲。”
- “每个标题都不一样，这怎么讲？”
- “小标题放在页里头。”
- “底下不一定每一页都得有横幅。没有必要的就不要加。”
- “案例一……问题是什么？解决方案是什么？”
- “把绿色的底子去掉……字颜色弄深一点。”
- “正文位置、P几P几这些都删掉。”
- “人工智能学院这个院标都少半截子。”

### 二、先停止执行旧版的几项错误要求

| 旧版做法或要求 | 本次纠正 |
|---|---|
| 给目录叠加每部分内容说明、节点小目录和页段 | 目录清楚呈现报告主题与顺序，删除解释性导读和页段索引 |
| 用任务对照表、关系台账代替总览 | 真正画出组成、层次和逻辑关系，再沿总图展开 |
| 每页顶部单独起标题，并以“无重复标题”为验收标准 | 同一主题的连续页使用一致的统摄标题，具体变化由页内小标题承担 |
| 把部分名、节点名缩在右上角 | 把统摄主题放到上方醒目位置，建立清楚的标题层级 |
| 每页添加“本页讲什么”、固定副标题或总结底栏 | 只保留帮助理解的页内小标题和必要结论，不按模板补句子 |
| 绿色背景、绿色卡片、灰色说明带、深色总结块 | 白底或无填充，深色文字，用线条、留白与对齐区分层次 |
| 规定总页数、每部分页数、每组至少几页、图示配额 | 按报告逻辑和内容需要合并、删减或展开，不设此类指标 |

标题可以简短，但不再用统一字符上限代替判断。应检查它是否准确、能否统摄内容、投影时是否清楚。

### 三、目录与总图分别怎样改

#### 1. 目录只呈现报告结构

目录让听众知道报告围绕哪些主题展开。先沿用现有内容的主要议题整理，例如：

- 智能体的技术构成
- 智能体安全风险与防护
- 安全评测与治理
- 典型安全事件与防控方案
- 可信协作机制
- 安全部署与持续验证

这是基于现稿的命名建议，不是教师指定的主题数量，执行时可按内容关系合并调整。

目录删除“本部分回答什么”“本部分分几讲”“正文位置”、页段、逐页标题索引和解释性小字。不再用缩小字号塞入更多层级，也不靠单纯放大字来解决结构问题。

#### 2. 总图必须展示内容关系

总图应让听众看清对象由什么组成、各部分是什么关系，以及后面按什么顺序展开。不能把标题列表放进方框，就当作总图。

全篇需要先建立技术、安全风险、防控与验证之间的总体联系。进入复杂主题时，再用该主题的总图统摄后续内容；已有总图足以说明关系的地方，不另加重复导读页。

下面是编辑执行说明，不能将此表直接复制进PPT：

| 主题 | 总图应画清什么 | 后续怎样展开 |
|---|---|---|
| 技术构成 | 本报告讨论的大模型智能体的主要部件、任务运行闭环，以及部件之间的调用与反馈关系 | 按图中的部件和运行关系展开；工具、外部记忆等按实际需要配置，不画成所有智能体都必须具备 |
| 风险与防护 | 基础设施、管理、协同、应用接口等层次，风险发生的位置及对应控制 | 按层次展开风险与防护；不要把架构层次画成先后执行阶段 |
| 评测与治理 | 能力、安全、适用规则和运行验证之间的分工，以及需要哪些证据 | 先说明要验证什么，再给评测、规则与证据；避免先堆文件和指标 |
| 典型事件 | 各案例的核心问题、出问题的环节，以及对应的防控方案 | 每个案例直接讲事件、问题与方案；不同案例之间不画虚假的因果链 |
| 可信协作 | 需要解决的信任问题、可采用的机制，以及链下仍需落实的校验 | 围绕具体信任问题展开；不笼统宣称区块链能够解决智能体安全 |
| 部署与运行 | 不同运行环境中的安全要求、控制措施、异常处置与复测关系 | 按环境和控制职责展开，说明措施在哪落实、如何验证 |

总图中的箭头应有明确含义，例如调用、反馈、约束或核验。并列关系用并列布局表达，不随意连成流程。先保留讲述需要的主干，细项留到展开页。

#### 3. 清理现稿中的索引式页面

- 将“任务执行过程与部件对照”等开篇对照页改为技术构成与运行关系总图，先建立整体认识。
- 将部分隔页中的节点清单、页段和“本部分回答”删去；与后面的密集总表统筹处理，形成可以直接开讲的总图或主题引入。
- 将“四层风险、控制与验证证据”“报送任务的能力、风险与治理核对”等表格中的有效关系提炼为总图；有独立分析价值的细表再放到相关内容中。
- 将“工具接入、案例复盘与协作风险”“可信机制、运行环境与持续防护”等关系台账退出正文，删除E编号、“正文位置”和页码引用。必要内容并入相应总图或论述。
- “全篇技术与安全关系总览”应提炼为前面的总体关系图，不能把原有密集表格整页搬到开头。
- 结尾保留行动要求，删除重复复述全篇内容的总结带。

### 四、标题层级怎样统一

顶部横幅承载统摄主题，位置醒目、样式一致。同一主题下的连续页保留这一标题；页内小标题说明当前具体论题，并靠近对应图文。

不要继续让左上大标题每页各说各话，再把真正的主题缩到右上角。也不要把全篇不同主题都写成同一个空泛标题。

可按以下关系处理：

| 顶部统摄标题示例 | 页内小标题示例 |
|---|---|
| 智能体的技术构成 | 模型、规划与工具的协同；上下文与外部记忆；任务执行与结果反馈 |
| 智能体风险与防护 | 基础设施层：供应链与资源风险；管理层：身份与授权；应用接口层：输入与工具边界 |
| EchoLeak案例复盘 | 外部邮件进入处理流程；指令越界的触发环节；外传路径与防控措施 |
| Replit数据库删除事件 | 事件经过；开发边界与生产数据风险；隔离、确认与恢复措施 |

教师举的“人工智能技术前沿—世界模型”属于页内小标题的示例。本报告应建立相应的统摄主题与具体论题关系，不照搬该内容。

标题应使用具体对象和专业概念，删去口语、制作说明、泛泛的“几个方面”“一些思考”，以及意义相同的反复改写。相邻页是否需要重复统摄标题，取决于它们是否仍在讲同一主题。

### 五、案例直接讲问题与方案

案例先用简短事实交代事件，再清楚标出“问题”和“防控方案”。如有必要，用图展示触发入口、越界环节和实际影响。不要先堆时间线、来源、评分和关系索引，让听众自己寻找结论。

以数据库误删案例说明表达方式：

**事件**  
编码智能体误删生产数据库。只保留材料能够支持的经过和影响。

**问题**  
工具执行越过预期的开发边界，影响生产数据。图中标清错误操作如何触及生产环境。

**防控方案（建议）**  
隔离开发与生产环境，分别配置访问凭证；对删除等高影响操作设置独立确认，并建立可验证的恢复机制。

如材料记录了涉事方实际采取的修复，应另写“已采取的处置”。防控建议不能写成对方已经实施的措施，也不能在没有证据时宣称风险已经解决。

其他案例沿用这种清楚的讲述关系，具体措施随问题变化，不强行套用相同结论。

### 六、白底、深字与完整院标

全页背景、正文卡片和文字底带统一使用白底或无填充。删除绿色大底、浅绿色铺底、灰色说明带及深色结论块。同步把原来的白字、浅色字改成黑色或深灰，避免只去底色而留下看不见的文字。

顶部横幅可以用白底、深色标题和细线实现。线条、边框或少量重点标识可使用深绿色；不再大面积铺色。底部横幅没有必要时删除，有必要保留的结论也用白底深字呈现，不逐页补一条总结。

图表中的白字深底也要同步处理。位图中固化的底块需要重绘或替换，不能只修改幻灯片背景。实景照片及完整院标保留原色，不做影响信息的统一去色。

将被裁掉的院标换成完整原图，等比缩放，使用完整适应画框的方式。检查图片裁剪、遮挡和边界，不能用残缺图标凑版。

用对齐、间距和留白组织版面。文字框放不下时先删冗句、调整图文或拆分内容，不通过持续缩小字号塞满一页。检查文字与自身文本框、外层卡片、连线、图片和页面边界的关系；不能只检查文本框内部。

删除目录和正文中的“P几”“正文位置”等编辑定位信息。普通页脚页码可按阅读需要保留，不放进标题，不在正文反复引用页段。

### 七、执行顺序与交付检查

先完成目录、总体关系图、首个主题的总图及对应展开页、一个代表性案例，让老师尽快看到新的结构与讲述方式；随后按同样的层级关系处理其余内容。不要等整份材料全部重做后才交审看稿。

执行顺序：

1. 白底深字；修复院标；删去导读说明、页段索引和无必要的底栏。
2. 重做目录和总图，确定后续内容沿什么关系展开。
3. 将统摄标题移到上方，具体论题改为页内小标题。
4. 将案例整理为事件、问题和防控方案，区分实际处置与建议。
5. 合并重复页面、调整图文，逐页检查可读性与遮挡，再导出审看稿。

交付时检查：

- 听众能否从目录看清报告主题，从总图看清内容关系？
- 展开页是否沿总图的顺序与分类讲述？
- 统摄标题是否醒目，同一主题是否保持连续？
- 页内小标题是否明确对应当前图文？
- 案例能否直接找到核心问题和防控方案？
- 是否仍有绿色或灰色文字底块、浅色字和残缺院标？
- 是否仍有“本部分回答”“正文位置”、页段或编辑编号？
- 是否存在文字越框、贴边、连线压字、图注遮挡或过密小字？

完成这些检查后交付可编辑PPT与阅读核验版。改稿台账留在独立文件中，不进入报告正文。验收围绕报告结构、讲述连贯性、专业表述和投影可读性，不再以页数、图数或标题唯一性计数。
